## 4. ТЗ: временный статичный сайт конгресса-2027

**Цель:** информационный статичный сайт (запуск ≤1 неделя), собирающий трафик к открытию регистрации (ноябрь 2026) и консолидирующий весь архив у себя. Без регистрации, без ЛК, без трансляций.

**Принципы:**
1. **Никаких внешних архивных ссылок** — весь архив живёт страницами внутри сайта, файлы (PDF, фото) хостятся у нас.
2. **Честные заглушки:** чего нет — прямо говорим «в разработке», не копируем контент-2026 под видом 2027.
3. **Структура = будущая модель платформы:** сайт размечаем так, как ляжет в модуль «конструктор мероприятий» Doctor.School (Событие → выпуск года → блоки: программа/спикеры/партнёры/материалы/фото). К ноябрю 2026 переезд на платформу + 301-редиректы.
4. RF-доступность хостинга обязательна (аудитория — врачи РФ; Cloudflare-зависимые решения исключены).

**Карта страниц:**


### Поправка от 2026-07-29 — профили компаний возвращены в карту (Issue #24)

Первая редакция карты (§4 выше) свернула каталог экспонентов в одну строку «/partners: уровни + контакт» ради запуска ≤1 недели: страницы `/company?i=<slug>` в карту не вошли **сознательно**. Владелец пересмотрел решение 2026-07-29 — профили нужны, поэтому в карту добавлен маршрут `/partners/<slug>`.

Что это меняет фактически:

- **22 профиля** — ровно столько компаний имели страницу на старом сайте (все 22 экспонента `/exhibition` 2026). Инфопартнёры (9) и организаторы (5+16) профилей не имели и не получают: `slug = null`, страница не генерируется.
- **Модель данных**: партнёр в `src/content/congress/<year>.yaml` получил поля `slug`, `address`, `contacts {email, phone}`, `description[]` — plain text, как и весь остальной контент (инвариант loader-swap: те же поля отдаст модуль платформы).
- **Миграция URL**: `infra/redirects.yaml` содержит карту `/company?i=<id>` → `/partners/<slug>/` на все 22 компании. Идентификаторы старого сайта (`dr.reddys`, `serve`, `CSCPharmaRussia`) живут только в этой карте.
- **Постеров/видео/материалов у профилей нет.** Старая разметка рисует модалки `poster1..3.jpg` и `video.mp4` для каждой компании, но это шаблон: на CDN оператора все эти файлы отдают 404 (проверено по всем 22, при том что `logo.png` из той же директории отдаётся). Спасать было нечего — в S3 по этой задаче не загружено ничего.

Принцип 2 («честные заглушки») при этом не нарушен: маршрут появляется только там, где под него есть спасённый контент.

## 5. План работ (следующие задачи под DSG2-11)

1. **Выгрузка активов** (до смерти ссылок): 5+ облачных папок фото, тезисы 2024 (Drive), тезисы 2023 (нужна авторизация Bitrix24 — owner-шаг), PDF-отчёт 2021 (достать браузером/Playwright), prog.pdf + material.pdf 2026, 12 JPG 2025 + превью с img1.creatium.ru; lazy-load видео-ролики 2024/2025 — проверить браузером, существуют ли.
2. **Сборка сайта** по карте §4. **Рекомендация — статик-генератор в репо bbm + свой хостинг** (сайт — на нашей инфре/Timeweb, тяжёлые фотоархивы — на Timeweb S3; DNS в Beget). Почему не Tilda: (а) структура контента должна жить как данные (YAML/JSON на год конгресса) — это готовая модель для платформенного модуля, из Tilda её потом придётся выковыривать руками; (б) 6 однотипных архивных страниц из шаблона агенты собирают за часы, в Tilda это ручная вёрстка каждой; (в) полный контроль 301-редиректов при переезде на платформу в ноябре (у Tilda редиректы ограниченные); (г) лимиты файлового хранилища Tilda против ~1 ГБ+ наших фотоархивов; (д) нет абонентки. Tilda оправдана только если критично визуальное редактирование контента Эдуардом без нас — но правок до ноября ожидается мало и они идут через нас. RF-доступность обязательна в любом варианте (поэтому свой хостинг, а не Vercel/Cloudflare-зависимые площадки).
3. **Наполнение архива** 2021–2026 по единому шаблону.
4. **DNS/домен** — перевести orthobio.ru на новый сайт (владение доменом — см. открытые вопросы).
